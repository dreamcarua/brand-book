/// 25 — MOBILE-FIRST SPEC

МОБІЛЬНИЙ — ГОЛОВНИЙ ЕКРАН

85% нашої аудиторії читає бренд з телефона. Дизайн який добре виглядає на 27"-моніторі дизайнера і ламається на 6"-екрані юзера — це провал. Цей розділ — стандарти для мобільної версії, що доповнюють розділ 09 UI-компоненти.

/// TOUCH TARGETS — МІН 44×44 PX

Apple HIG, Google Material і WCAG 2.5.5 рекомендують мінімум 44×44 px (CSS) для будь-якого clickable елемента. У нас — так само. Менше — користувач промахується і дратується.

/// ❌ ПОГАНО — 24×24px
×

Кнопка закриття 24px. На iPhone Pro = 9pt — складно потрапити пальцем. Фрустрація = вийде з flow.

/// ✅ ДОБРЕ — 44×44px (видимий 24px)
×

Видимий icon 24px, але hit area 44×44. Padding робить кнопку фізично кліклабельною.

/// ✅ ІДЕАЛЬНО — 48×48px (Material)
×

48px = Material Design recommendation. На дрібних екранах (iPhone SE) — особливо комфортно.

Spacing between touch targets: мін 8px (idеально 12px). Якщо кнопки впритул — користувач промахується на сусідню.

/// THUMB ZONES — ДЕ ПАЛЕЦЬ ДОТЯГУЄТЬСЯ

Більшість користувачів тримають телефон однією рукою. Це означає що нижня частина екрана = easy reach, а верхня = hard. Розміщуй критичні елементи (CTA, головна навігація) у easy zone.

⚠ HARD ZONE
~ STRETCH
✓ EASY ZONE
RIGHT HAND THUMB
⚠ HARD
✓ EASY
LEFT HAND THUMB
⚠ HARD
✓ EASY ZONE
TWO HANDS

Практичні висновки:

  • Primary CTA — внизу екрана (sticky bottom bar або bottom modal).
  • Bottom navigation — у самому низу (де natural thumb position).
  • Verхні елементи — статус, breadcrumb, заголовок секції (не критичні дії).
  • Бургер-меню — top-left = compromise, але виправдане якщо є sticky bottom.
  • Назад-кнопка — top-left (iOS swipe-back + visible button).

/// СТАНДАРТНІ МОБІЛЬНІ ПАТЕРНИ

/// BOTTOM SHEET

ЗАМІСТЬ MODAL

На мобільному — bottom sheet (як у Maps). Swipe-down закриває. Less aggressive ніж full-screen modal.

/// PULL-TO-REFRESH

СТАНДАРТНИЙ ПАТЕРН

Лента постів / запитів — обовʼязково pull-to-refresh. Користувачі очікують, що це є.

/// SWIPE ACTIONS

SWIPE LEFT/RIGHT

Списки = swipe для дій. swipe-right = approve/like, swipe-left = delete/decline. Як у Mail/Telegram.

/// FAB

FLOATING ACTION BUTTON

Primary action як FAB у bottom-right (Material). Завжди видимий. Для DC — червоний pill з іконкою.

/// STICKY HEADER

ШАПКА ПРИ SCROLL

Чорна шапка з лого і CTA "Взяти участь" — sticky зверху при scroll вниз. Зникає при scroll up.

/// INFINITE SCROLL

НА ФІДАХ

Лента постів / архів промоакцій — infinite scroll з spinner внизу. Не пагінація на мобільному.

Скейлинг типографічної шкали з розділу 07 для mobile. Базовий розмір на мобільному — 16px (Apple/Google default).

/// PERFORMANCE — ШВИДКІСТЬ

Аудиторія DC у Україні значна частка на 4G/3G (особливо у регіонах). 3 секунди до first paint — це наш бар. Більше — bounce rate стрибає на 50%+.

/// LCP

< 2.5 СЕК

Largest Contentful Paint — головна картинка/заголовок видна за 2.5 сек на 3G.

/// FID

< 100 МС

First Input Delay — кнопки реагують через 100ms максимум.

/// CLS

< 0.1

Cumulative Layout Shift — макет не "стрибає" при загрузці.

/// IMAGES

WEBP + LAZY

Всі зображення у WebP (фолбек JPEG). Lazy-load для below-fold. Розмір ≤200KB на hero.

/// FONTS

SUBSET

Google Fonts через display=swap + preload. Latin + Cyrillic subset. Не вантажити italics якщо не використовуєш.

/// JS BUNDLE

< 200KB GZIP

Початковий JS bundle — макс 200KB. Інше — lazy-load (code splitting).
